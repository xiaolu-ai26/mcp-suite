只需要理解这三件事

兑换码是订单交付给你的开通凭证，使用一次后不能再兑换，兑换那一刻开始算 30 天。API key是你自己的拆解库访问凭证，不是大模型 API key。MCP 连接器是让 Agent 真正调用拆解库工具的配置，不是一段普通聊天提示词。

服务器名称：bench（AI 赛道爆款拆解库）
服务器地址：https://savegems.top/bench/mcp
传输方式：Streamable HTTP / HTTP
Header 名称：Authorization
Header 值：Bearer YOUR_API_KEY

这里只显示占位符。兑换页的复制按钮会替换成你的实际 key。Bearer 后保留一个空格，不能把 key 加在 URL 后面。首次接入使用固定 Bearer 凭证，不要误选 OAuth 登录。

01 / WorkBuddy

先让 Agent 检查当前版本的自定义连接器入口；没有代配置权限，就在连接器管理中手动添加。选择远程 HTTP、填写服务器 URL，并在 Headers 中设置 Authorization。支持 JSON 的页面可粘贴兑换页生成的配置。保存、启用后，新建任务再测试。

依据：WorkBuddy 连接器文档flomo 作为服务方的接入实操

02 / 豆包工作

指豆包工作电脑版，而不是普通豆包聊天。参考入口为“技能·连接器·伙伴 → 新建 → 新建自定义连接器”。填写 HTTP、服务器 URL 和自定义 Headers；保存后在新工作任务中启用连接器。

本次未取得豆包自身完整公开配置说明，入口参考服务方 flomo 的公开教程。若当前版本缺少 HTTP 或 Headers，请反馈实际页面，不要猜配置文件位置，也不要把 key 填到网址里。

依据：flomo 官方 Token 接入教程

03 / 千问办公

进入“扩展 → 连接器 → 添加”，选择粘贴 JSON 配置；也可手动选择 Streamable HTTP，填写地址和 Authorization Header。兑换页提供该客户端格式的配置。保存并开启后，必要时新建任务让工具生效。

依据：阿里云千问办公连接器文档

04 / Codex

Codex 的 HTTP MCP 可以使用 URL、bearer_token_env_var 或 http_headers。它的配置格式是 TOML，不是普通 MCP JSON。兑换页生成的配置应合并到用户私有配置，不要整份覆盖项目配置。

[mcp_servers.bench]
url = "https://savegems.top/bench/mcp"
bearer_token_env_var = "BENCH_API_KEY"

这是环境变量方式，必须让实际运行 Codex 的进程读取到该变量才生效。仅在某个终端临时设置，不保证桌面应用能够继承。兑换页同时提供已填值的 Header 配置；使用时应保存在私有配置，避免进入代码仓库。

依据：OpenAI 官方 MCP 文档

05 / Claude Code

使用远程 HTTP MCP，并设置 Bearer 请求头。优先通过用户或本地作用域配置，使用 /mcp 核对连接。本产品上线时在本机 Claude Code 用独立测试 key 真实调用过三个工具；这不代表你的客户端版本与作用域一定同样可用。

Claude Code 与普通 Claude 网页／桌面客户端不是同一套配置。普通 Claude 的自定义连接器需要单独确认其鉴权方式；只看到“支持 MCP”不能推断它一定接受本服务的固定 Header。

依据：Claude Code 官方 MCP 文档

更多客户端 / Hermes、OpenClaw

Hermes Agent：官方支持在用户配置中的 mcp_servers 注册 HTTP 服务器及请求头。使用本机支持的安全凭证方式，保留其他服务器，加载后检查工具。

OpenClaw（小龙虾）：当前文档中的出站 MCP 放在 mcp.servers，可以从 Settings → MCP 管理。它不同于 mcp serve；后者是把 OpenClaw 暴露成服务器，不能用来替代接入本拆解库。先核对本机版本与运行时，再配置，勿自动安装不明桥接包。

其他客户端：包括 Cherry Studio，可按通用字段尝试，但本产品尚未完成它们的接入验收。

依据：Hermes 官方配置参考OpenClaw 官方接入文档

三个工具分别干什么

bench_search：按 topic（选题分类或来源关键词）、format（图文／视频）、tag（标题公式／内容角度／话题词）、platform、time_window、keyword 筛选，支持 limit 与 offset 翻页。约一半记录的发布时间原始资料没有记录，带 time_window 时这些记录会被排除，而不是猜一个日期塞进去。

bench_detail：按 id 取单条的全部业务字段。

bench_taxonomy：返回选题分类、标题公式、封面版式、内容角度、平台、粉丝区间、破圈分级各自的取值和条数，并在 coverage_notes 里说明哪些维度本期未标注、为什么。先调它，再决定用什么词去 search，能省很多次无效调用。

返回里有什么：公开链接、原标题、平台、图文/视频、可考证的发布时间、
              粉丝量级区间、破圈分级词、原创标签、原创拆解结论、观察日期
返回里没有什么：笔记/视频正文、逐字稿、图片、封面图与视频地址、
                点赞收藏评论分享播放等精确数字、赞粉比数值

什么才叫“接入成功”？

  1. 客户端完成连接，工具列表中出现 bench_search、bench_detail、bench_taxonomy，名称可能带客户端前缀。
  2. 只实际调用一次 bench_search，参数 limit=1，先不加筛选条件。
  3. 收到真实工具响应，保留返回的记录 ID、原标题、公开链接及观察日期；执行成功但零结果、鉴权失败和未调用工具是不同状态。

凭证、边界与售后

选择“复制带 key 的指令”会将私人凭证放入剪贴板，粘贴到 AI 后可能进入该服务商的对话存储。要求 Agent 不回显，只能减少再次暴露，不能保证删除已经上传的内容。更稳妥的方法是手动把 key 填到客户端的私有连接器设置。

本网站不把 key 写入 localStorage、sessionStorage 或网址，但你主动复制的剪贴板、密码管理器和第三方 Agent 有各自的存储行为。清除本页凭证不等于撤销 key。泄露或丢失时，请通过原购买渠道提供订单凭证联系卖家处理，勿公开发 key。

链接可用性（2026-09-10 实测）：小红书笔记链接带时效性参数，库里这批多数已不能在电脑网页端直接打开，会提示需在小红书 App 内查看；抖音、TikTok 链接实测可直接打开。可行的做法是用返回的原标题到小红书 App 内搜原文，链接作为出处留档。工具返回里的 link_note 字段会重复说明这一点。

内容边界：库中每条指向的都是他人公开发布的内容，本服务提供的是链接与我们自己的拆解判断，不提供内容副本。请自行判断是否借鉴，不要整段搬运他人作品。链接可能因作者删除或平台策略而失效，本服务不承诺长期可访问。
