## 采集通道（按优先级）

### 1. 北森zhiye.com API（最快，优先尝试）
```
GET https://{company_slug}.zhiye.com/api/job/list?pageSize=20&pageIndex=1
```
常见slug猜测：公司拼音或英文名（如`gree`、`haier`、`midea`、`byd`、`catl`等）
- 列表接口通常直返岗位标题、地点、职责、要求
- 每家取1-3条即可，不追求完整采集

### 2. 飞书招聘API
```
POST https://{slug}.jobs.f.mioffice.cn/api/v1/search/job/posts
Body: {"offset":0,"limit":10,"job_category_id_list":[],"tag_id_list":[],"location_code_list":[],"recruitment_id_list":[],"portal_type":6,"function_list":[]}
Headers: Content-Type: application/json, Origin: https://{slug}.jobs.f.mioffice.cn, Referer: https://{slug}.jobs.f.mioffice.cn/
```
详情端点（免签名）：
```
GET https://{slug}.jobs.f.mioffice.cn/api/v1/job/posts/{id}?portal_type=6
```

### 3. 国聘API（央企/国企）
```
POST https://www.iguopin.com/api/job/search
Body: {"keyword":"企业名","page":1,"pageSize":20}
```

### 4. MokaHR
URL格式：`https://app.mokahr.com/campus-recruitment/{slug}/{numeric_id}#/jobs`
需通过搜索引擎找正确URL，或用浏览器渲染采集

### 5. 企业自建招聘站API
需抓包分析，常见模式：
- `https://career.{company}.com/api/jobs`
- `https://jobs.{company}.com/api/v1/positions`

### 6. 浏览器自动化（最后手段）
仅在API全部失败时使用，每家取1-3条

## 执行步骤

1. **先检查哪些企业已上线**：读取jobs.json，按recruitment_unit匹配，跳过已上线且有详情的企业
2. **逐家采集**：按通道优先级尝试，每家取1-3条真实岗位
3. **合并去重**：新岗位按detail_url去重，合并到jobs.json
4. **备份→写回→重启→验证**
5. **输出报告**：每家企业的采集状态（成功/阻塞/已上线）、岗位数、来源

## 阻塞处理

- 企业无公开招聘页面 → 标记"无公开招聘入口"，跳过
- 需要登录/验证码 → 标记"需登录"，跳过，不绕过
- API返回空 → 尝试下一个通道，全部失败则标记"无公开岗位"
- 超时 → 重试1次，仍失败则标记"超时"

## 交付物

1. **采集报告**：100家企业逐家状态（成功/阻塞/已上线）、岗位数、来源、阻塞原因
2. **新增岗位数据**：已合并到jobs.json
3. **最终统计**：新增企业数、新增岗位数、生产总企业数/总岗位数
4. **健康检查验证**：重启后health端点返回

## 注意事项

- 每家1-3条即可，不追求完整采集，重点是企业覆盖面
- 优先保证数据真实性，description必须来自真实招聘页面
- 已上线的企业如果只有标题没有详情，可以补充详情，但不要重复创建
- 校招岗位优先，实习和社招也可以但要明确标记
- 不要因为一家企业阻塞就停止，继续做下一家
- 全部完成后统一合并发布，不要每采一家就重启一次
