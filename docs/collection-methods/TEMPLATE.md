# 方法条目与回填模板

最后更新：2026-10-01。复制到最接近的现有文档，不为每次事故新建一份方法文件。

## 方法 ID：名称

- 最后验证：日期；验证者/执行任务；源码基线或受审文件 SHA。
- 等级：本项目运行实证 / 本项目源码与回归覆盖 / 参考未实施。
- 适用输入：来源、数据类型、范围、身份字段、输出目标。
- 选型条件：为什么使用该协议；何时不适用；访问与 robots 依据。
- 具体步骤：获取 → 证据 → 验证 → 合并 → 发布/交付；预算、锁与恢复点。
- 现成代码指针：仓库相对路径、真实符号；参考代码注明固定 commit。
- 已验证案例：触发条件、最小修复、脱敏回归样本、真实终态；私有证据仅列相对文件名。
- 失败反例：造成少采、误下架、重复、身份混淆或假成功的具体条件。
- 验收：可核分母、ID/字段差异、SHA、阶段回执、人工介入；未知项明确标注。
- 费用及登录：请求/计算/存储/平台额度；是否登录；现有订阅与新 API 账单分开。
- 待证据：实现完成、离线回归、自然 run、供应商真实调用分别列出。

维护顺序：先记录实际修复与证据，再抽象方法；项目事故细节由执行线的 [踩坑正文](../qiuzhao-collection-pitfalls.md) 维护；每日事实仍仅维护 `docs/qiuzhao-daily-delivery.md`。不把“建议”改为“已部署”，不把技术检查改为用户验收。

检查清单：相对链接可解析；代码符号存在；最后验证时间有依据；未复制密钥/原始私有数据；未复制每日计数；费用与登录边界清楚；回归与真实运行区分；新方法不重复旧条目。
